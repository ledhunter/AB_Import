# 🎯 Бизнес-презентации об эффекте ИИ по типам импорта

## 📋 Описание

Для каждого крупного типа импорта (Квартирограмма, Финмодель, …) рядом с кодом лежит **парная бизнес-презентация** в двух форматах:

- `presentation-ai-<type>-import.md` — исходник в Markdown (для правок и истории)
- `presentation-ai-<type>-import.html` — интерактивный самостоятельный HTML-файл с навигацией стрелками, dots, Home/End

Цель — показать бизнесу эффект использования ИИ при разработке: «план / факт», ускорение пользователя, накладные расходы, окупаемость. **Аудитория не техническая** — формулировки соответствующие.

---

## ✅ Правильная реализация

### Структура (9 экранов: титул + 8 слайдов)

```
Слайд 1 (титул)      — название, под-заголовок, бейджи (период, стадия)
Слайд 2 (контекст)   — цель + особенности предметной области
Слайд 3 (объём)      — таблица возможностей + прогресс по неделям
Слайд 4 (ценность)   — 5 карточек: Скорость / Надёжность / Универсальность / Прозрачность / Экономия
Слайд 5 (план/факт)  — таблица сроков + где ИИ дал максимальный эффект + цитата
Слайд 6 (пользователь) — Было / Стало + блок ускорения × N + KPI-grid
Слайд 7 (качество)    — побочные эффекты (база знаний, автотесты, отчёты, готовность к новым форматам)
Слайд 8 (расходы)     — таблица накладных + insight о разовой настройке
Слайд 9 (итоги)       — KPI-grid + главный вывод + окупаемость
```

### Бизнес-формулировки вместо технических терминов

| Технический термин | Бизнес-формулировка |
|---|---|
| ОКС | объект строительства |
| ИСР, WBS | бюджет, статьи бюджета |
| ГФ, CostItem | график финансирования, статья графика |
| ТЭП | ключевые показатели объекта |
| ДДУ, ShareAgreement | договор |
| ГК | Группа компаний |
| layout, шаблон заказчика | вариант оформления, файл разной структуры |
| pipeline, snapshot, find-or-create, pre-check | автоматическая последовательность, защита от дубликатов, проверка перед загрузкой |
| API, CRUD, DTO, JsonElement, HAR, listview | (не упоминать), «работа с разделами Visary» |
| маппер, парсер, БД, UI | связанные части системы |
| идемпотентность | не плодит дубликаты |

### Кто предоставляет Excel-файлы

> **Сотрудники компании** (не «заказчики»). Конкретные шаблоны (Журавли, Репино-Парк, Ежевика) **не упоминать** — это внутренние названия проектов.

### Статус «ещё не готово»

Если сервис не вышел в продуктив:

- Период: `с DD.MM.YYYY` (без закрывающей даты)
- Бейдж: `Финальная стадия`
- Подзаголовок шапки: `Статус: Финальная стадия разработки — реализованы все ключевые сценарии, идёт стабилизация`
- В слайде «Объём»: блок ⚠️ «Импорт ещё не готов — находится в финальной стадии…»
- В слайде «Итоги»: финальная плашка ⚠️ «сервис находится в финальной стадии разработки»
- Прогресс-бар недели N: последний сегмент **не закрашен** (4 из 5 = 80%), строка «Финал → готово к продуктиву» **отсутствует**
- Заголовок слайда «Что получит бизнес» (будущее время)

### HTML-шаблон

Стиль наследуется от [presentation-ai-rooms-import.html](../presentation-ai-rooms-import.html) — фирменные цвета `--red: #ef3124`, чёрный/серый, single-file, навигация работает оффлайн (`<nav>` + dots + клавиатура). При создании новой презентации проще всего **скопировать существующий HTML** и переписать только контентные секции (`<section class="slide">`).

### План/факт и ускорение пользователя

Числа берутся от заказчика задачи. Формат:

```markdown
| Этап | План (дней) | Факт (дней) | Сокращение |
|------|:---:|:---:|:---:|
| Аналитика     | план | факт | **−X%** |
| Разработка    | план | факт | **−X%** |
| Тестирование  | план | факт | **−X%** |
| ИТОГО         | сумма | сумма | **≈ −X%** |
```

Слайд «Ускорение пользователя»: блок Было/Стало с большими числами, под ним чёрный effect-блок `× N` крупно, KPI-grid с экстраполяцией на неделю/день при типовом темпе.

---

## ⚠️ Важно

- **Источник числовых данных** — заказчик задачи (план/факт по этапам, ручное время пользователя). Не выдумывать.
- **Период разработки** считается **по факту первого и последнего FinModel-коммита** в git (`git log --since=… --grep=…`), а не «за месяц».
- **Прогресс по неделям** строится из реальной хронологии коммитов с группировкой по фичам, не выдумывается.
- HTML и MD **должны быть синхронны**. При правках MD — обновлять HTML точечными `Edit`-ами, не пересоздавать целиком (потеряются CSS/скрипт).
- При экспорте в PDF/печати — навигация и темный фон счётчика не нужны, но это **отдельная задача**; стандартный HTML рассчитан на показ в браузере.

## ❌ Типичная ошибка

### 1. Технические термины в тексте слайдов

```markdown
<!-- НЕПРАВИЛЬНО: бизнес-аудитория не понимает -->
Создание Графика финансирования Главы 1 (CostItem по кварталам) ✅
Pre-check ИСР: если бюджет уже залит — не дублируем ✅
Поддержка двух layout-ов листа «План» (Журавли + Репино-Парк) ✅
```

```markdown
<!-- ПРАВИЛЬНО -->
Создание графика финансирования по кварталам ✅
Проверка перед загрузкой: если бюджет уже залит — не дублируем ✅
Поддержка файлов разной структуры ✅
```

### 2. «Заказчик» вместо «сотрудник компании»

Excel-файлы поступают **изнутри компании**. Формулировка «реальные шаблоны заказчиков» создаёт впечатление внешнего интегратора.

### 3. Прошедшее время «уже сделано» при незавершённой разработке

```markdown
<!-- НЕПРАВИЛЬНО: создаёт впечатление готового сервиса -->
Финал (27.05 – 29.05) ▰▰▰▰▰ Стабилизация → готово к продуктиву
```

Если сервис в работе — последний сегмент **не закрашиваем** и строки про финал не пишем. Иначе бизнес ждёт продуктив, а его нет.

### 4. Пересоздание HTML целиком при мелких правках

`Write` поверх HTML стирает любые ручные правки CSS/JS, которые пользователь мог внести между нашими прикасаниями. Точечный `Edit` сохраняет всё, что не относится к изменяемой строке.

## 🎯 Чек-лист перед показом

- [ ] Период разработки и план/факт сверены с заказчиком задачи
- [ ] В тексте нет технических аббревиатур (ОКС/ИСР/ГФ/ТЭП/ДДУ/ГК/CRUD/API/DTO)
- [ ] В тексте нет служебных терминов разработки (layout / pipeline / snapshot / mapper / parser)
- [ ] Конкретные названия проектов-источников файлов (Журавли, Репино-Парк, Ежевика) убраны
- [ ] Файлы предоставляют «сотрудники компании», не «заказчики»
- [ ] Если сервис в разработке — все 4 признака статуса проставлены (бейдж, плашка слайда 2, плашка слайда 8, прогресс-бар не закрашен полностью)
- [ ] Заголовок слайда ценности — «Что получит бизнес» (будущее время) при незавершённой разработке, «Что получил бизнес» в итогах (прошедшее, ретроспектива)
- [ ] HTML открывается в браузере, навигация работает (стрелки/Home/End/dots)
- [ ] Прогресс по неделям соответствует реальной хронологии коммитов
